03Case em destaqueFeatured case

Agente de IA no ERP criado por mimAn AI agent in an ERP I built

VPSYSTEM Em produçãoIn production Código confidencialConfidential code

Um chat dentro do ERP onde a equipe pergunta sobre pedidos, carteira e produção em português e recebe a resposta com os dados reais do Oracle, com controle de acesso e consultas somente leitura.

A chat inside the ERP where staff ask about orders, backlog and production in plain Portuguese and get answers from the company's real Oracle data, with access controls and read-only queries.

O problemaThe problem

Responder perguntas do dia a dia exigia um relatório pronto ou um pedido ao time técnico. Abrir o banco para uma IA, por outro lado, não podia expor dados de outros setores nem permitir escrita.

Everyday questions needed a ready-made report or a request to the tech team. Opening the database to an AI could not risk exposing other departments' data or allow writes.

O que desenvolviWhat I built

  • Motor de execução dinâmica de consultas
  • Catálogo semântico que traduz termos do negócio para o banco
  • Controles de permissão, escopo de acesso e leitura de dados
  • Contexto entre perguntas da mesma conversa
  • Testes automatizados e homologação com dados reais
  • Dynamic query execution engine
  • Semantic catalog that maps business terms to the database
  • Permission, access-scope and data-read controls
  • Context across questions in the same conversation
  • Automated tests and validation against real data

DecisõesDecisions

  • O modelo de IA nunca escreve SQL. Ele devolve um plano estruturado, e código determinístico monta a consulta.
  • Tudo é bloqueado por padrão. Só roda o que foi liberado explicitamente.
  • Pergunta ambígua recebe uma pergunta de volta, nunca um palpite.
  • The AI model never writes SQL. It returns a structured plan, and deterministic code builds the query.
  • Everything is denied by default. Only explicitly allowed queries run.
  • An ambiguous question gets a clarifying question back, never a guess.

O caminho de uma perguntaHow a question travels

Sete etapas entre o texto livre e o banco de dados.

Seven steps between free text and the database.

  1. 01PerguntaQuestionTexto livre, em português.Free text, in Portuguese.
  2. 02Plano da consultaQuery planO modelo devolve um plano estruturado ou pede esclarecimento.The model returns a structured plan or asks for clarification.
  3. 03ValidaçãoValidationPeríodo, limites e relacionamentos conferidos antes de existir SQL.Period, limits and joins checked before any SQL exists.
  4. 04Permissão e escopoPermission and scopeSó segue se o usuário pode ver aqueles dados, já filtrados pelo escopo dele.Continues only if the user may see that data, already filtered to their scope.
  5. 05CompilaçãoCompilationSQL gerado por código determinístico.SQL generated by deterministic code.
  6. 06VerificaçãoVerificationSó SELECT, parâmetros vinculados, só tabelas conhecidas.SELECT only, bound parameters, known tables only.
  7. 07ExecuçãoExecutionUsuário Oracle somente leitura.Read-only Oracle user.

Validação, permissão e verificação acontecem antes de qualquer consulta chegar ao Oracle.Validation, permission and verification all happen before any query reaches Oracle.
